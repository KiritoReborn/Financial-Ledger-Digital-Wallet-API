# D02 reversal service and `POST /transactions/{id}/reverse`

## Summary

Implemented the D02 transaction reversal service in
`backend/app/services/reversal.py` and wired `POST /transactions/{id}/reverse`
into `backend/app/api/admin.py` using the live shared backend infrastructure:

- **Transaction ownership (`H03`, `FR-3.1`)**: Uses the caller-owned
  `BEGIN IMMEDIATE` connection from `SqliteDatabase.transaction()` and never
  begins, commits, or rolls back inside `reverse_transaction`.
- **Admin authentication (`H04`, `FR-4.4`, `NFR-SEC-2`, `BR-5`)**: Enforces
  constant-time verification (`hmac.compare_digest` over SHA-256 digests) of
  both the bearer token and `X-Admin-Key`, and verifies
  `authenticated_user_id(conn, ...) == ADMIN_ID` before running the operation.
  See [[constant-time-secret-comparison]].
- **Idempotency (`B01`, `FR-2.5`, `FR-2.9`, `FR-2.10`)**: Validates
  `Idempotency-Key` via `parse_idempotency_key` (`400 IDEMPOTENCY_KEY_MISSING`,
  `422 VALIDATION_ERROR`) and wraps execution in `run_idempotent` with
  `scope="REVERSAL"` and `target_id=txn_id`. Failed reversals roll back without
  persisting an idempotency record so retries with the same key succeed once
  funds are available.
- **Posting & invariants (`C04`, `FR-4.2`, `FR-4.3`, `FR-4.5`)**: Validates
  target existence (`404 NOT_FOUND`), reversible type `DEPOSIT`/`TRANSFER`
  (`422 NOT_REVERSIBLE`), single reversal (`409 ALREADY_REVERSED`, backed by
  `UNIQUE` `reverses_txn_id`), and sufficient user debit balance
  (`422 INSUFFICIENT_FUNDS`), then posts mirrored `DEBIT`/`CREDIT` entries via
  `LedgerPoster` (`PostTransaction`). See [[sqlite-immutability-triggers]],
  [[projects/2026-11-20-c04-posting]], and [[2026-11-20-d03-reconciliation]].

## Verification

- `backend/tests/test_reversal.py`: 16 tests covering C03 contract fakes
  (`MemoryTransactions`, `FakePostTransaction`), C04 `LedgerPoster` + `reconcile`,
  end-to-end HTTP flows (`POST /users` -> `POST /wallets` -> `deposit` ->
  `transfers` -> `reverse` -> `GET /admin/reconcile`), insufficient-funds
  rollback & same-key retry, concurrent double-reversal race (`201` + `409`),
  concurrent same-key replay (`201` + `201`), auth rejection, and `NFR-SEC-7`
  error sanitization.
