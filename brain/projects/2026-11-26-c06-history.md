# C06 history integration with the live ledger (AI-assisted)

The public API mounts both history routes in the normal app factory. Bearer
lookup uses Member A's resolver on the same read-only SQLite snapshot as the
history queries. Transfer details are available to both participants. Wallet
history belongs to the wallet owner and uses an exclusive, newest-first
cursor.

The integration test starts with an empty migrated SQLite file and calls
registration, wallet creation, deposit, transfer, replay, reversal and
reconciliation. It checks that replay leaves one history entry for the
transfer, that the reversal appears first, that the original deposit appears
on the next page, and that unrelated users cannot read the records.

`python -m pytest -q tests/test_history.py backend/tests/test_history_integration.py backend/tests/test_api_health.py`
passed 47 tests. [History integration test](../../backend/tests/test_history_integration.py).

On November 28, the feature was applied to the rewritten main baseline
`1ec69e1`. The routes publish response shapes in FastAPI and use the shared
SQLite error mapping. The focused suite passed all 47 tests and the complete
Python suite passed all 645 tests on Python 3.11.
