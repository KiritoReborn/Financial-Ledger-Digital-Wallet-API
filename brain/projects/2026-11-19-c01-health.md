## Design and progress

- The API factory registers only GET /health, without authentication.
- A small injectable readiness interface separates HTTP handling from checking
  SQLite. It is not the financial connection/transaction provider.
- The production adapter opens the existing file with mode=ro, enables query_only,
  reads the catalog and closes the connection. It never creates or migrates a DB.
- Errors use generic INTERNAL_ERROR or documented DATABASE_BUSY without SQL,
  filesystem paths, exception messages or secret values.
- The existing team CI file is unchanged. A separate component check installs the
  API dependencies and runs health tests on Python 3.11.
