# C05 rollback and process recovery (AI-assisted)

The recovery tests use a temporary database with the same migrations and
SQLite settings as the API. They check that an injected exception after
posting and writing a simulated replay row rolls back both changes through
the shared transaction provider. A retry then commits one balanced pair of
entries and one replay row.

A separate process exits without cleanup before and immediately after commit.
Reopening SQLite verifies that uncommitted changes disappear, committed changes
survive, the balances match, and both the integrity and foreign-key checks pass.
The HTTP fixture supplies the replay row for the test. End-to-end replay testing
still needs Member B's production idempotency wrapper.

All 291 Python tests and Ruff passed on this branch.

```sh
python -m pytest -q backend/tests tests
python -m ruff check .
```
